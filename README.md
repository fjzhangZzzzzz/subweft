# Subweft

**Mihomo 订阅与策略配置服务。**

[English](README.en.md) · [设计](docs/design.md) · [支持矩阵](docs/support-matrix.md) · [验收标准](docs/acceptance.md)

> 当前是已确认的设计基线，尚无可运行应用或发布工件。下列能力是实施目标，不是已实现功能；请勿用于生产。

Subweft 面向个人和家庭，把订阅、手工节点、策略组、规则、配置发布及设备链接维护集中到 Web 表单。服务持有上游凭据，设备通过独立授权获取渲染后的 Mihomo 配置。

## 产品目标

- 全部日常业务操作使用结构化表单，包含高级字段；YAML 仅用于导入、导出和只读预览。
- 共享订阅和手工节点，多份配置方案独立维护组、规则、DNS及客户端参数。
- 策略组自由组合多个订阅、标签、节点及其他合法策略组，显示筛选结果和来源。
- 草稿经校验后原子发布，保留有效缓存、不可变版本及回滚能力。
- 每台设备独立链接，支持方案切换、暂停、吊销和凭据轮换。
- 原生标准 OIDC，首先验收 Pocket ID；Nginx 只负责 HTTPS 基础反代。
- Go、SQLite与内嵌 React Web UI，面向单实例部署。

首版范围以[支持矩阵](docs/support-matrix.md)为准。解析成功、配置校验成功和真实连接成功分别记录；不宣称覆盖所有 Mihomo 字段、客户端或未来版本。

## 操作路径

添加来源 → 配置方案中选择组成员和规则 → 校验及预览 → 发布 → 新建设备并导入客户端。

普通配置更新和切换方案保持设备 URL 不变，客户端刷新后取得新版本。吊销只阻止后续下载，不能收回已下载的代理凭据。服务不会远程控制客户端。

## 部署边界

正式运行目标是 Linux amd64、arm64；Windows 用于开发和本地试用。首版客户端验收范围为本机 Clash Verge。尚无经过验收的安装命令、容器镜像或客户端集成。

应用自身不运行供设备使用的代理内核；配置校验独立调用固定版本 Mihomo。安装升级、证书、主机运维和整机备份恢复由部署方负责。实例业务状态归数据库，不由部署脚本重复投射覆盖。

使用新的独立子域名和 URL，不兼容旧命令、下载链接、认证或 Git 推送渲染流程。迁移需要重新生成设备链接并进行客户端验收。
