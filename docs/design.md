# 产品设计

本文是已确认的实施依据。它定义目标行为，不表示功能已实现。覆盖范围见[支持矩阵](support-matrix.md)，实现完成须满足[验收标准](acceptance.md)。

## 定位与边界

Subweft 面向个人及家庭。原生接入标准 OIDC，首先验收 Pocket ID；服务管理订阅、节点、组、规则、渲染、发布和设备授权。Nginx仅做HTTPS基础反代，不保存业务Token或生成配置。基础设施运维继续由部署方的既有工具承担。

不建设开放注册、计费、多租户运营体系、复杂权限平台、插件执行平台或供设备使用的代理内核。不要求同时支持其他配置内核。新域名、新URL，不兼容旧链接、认证或命令。

## 对象和归属

| 对象 | 内容和归属 |
|---|---|
| 订阅 | 远程地址或本地内容、标签、启停、设备更新周期、请求头、筛选及健康检查 |
| 来源节点 | 本地订阅可逐项维护；远程节点由设备解析，服务端不枚举或虚构节点状态 |
| 手工节点 | 通过协议表单维护，或从来源节点复制后独立维护 |
| 配置方案 | 独立拥有组、规则序列、DNS及其他客户端参数；可以复制，不做多层继承 |
| 策略组 | 属于方案；组合订阅、动态标签来源、节点和其他合法组 |
| 规则集 | 可复用自建内容或受管理的外部公共规则资源 |
| 发布版本 | 配置及远程定义、本地资源、生成工件和结构校验结果的不可变集合 |
| 设备 | 归属于使用者，绑定一份方案，拥有独立下载凭据和状态 |

订阅和手工节点是共享来源；方案之间的组和规则编辑相互独立。删除被引用资源时显示影响范围并拒绝破坏性删除，提供改绑或停用路径，不静默级联删除。

## 来源与节点

接收约定范围内的 Clash/Mihomo provider YAML、完整配置中的节点、常见代理URI列表及Base64编码。支持链接、上传文件和粘贴输入，设置体积、数量和解析时间限制。

完整配置默认只提取节点；导入方案、DNS或规则必须经过单独的字段检查和预览。未知类型、字段和解析错误逐项报告，不静默跳过，不依赖公共转换服务。

远程节点随设备更新，名称替换、前后缀和筛选通过表单定义，由设备执行。本地节点可单独改名、排除及复制。升级遇到旧的远程逐节点覆盖时保留并阻止相关发布，可通过表单转换为本地集合；不能静默丢失修改。

订阅可通过标签分类。组既可明确选择多个订阅，也可选择全部或匹配标签的订阅。筛选节点是独立步骤，支持包含、排除及可预览的高级条件。本地成员可预览，远程来源展示筛选定义而不虚构命中结果。订阅前缀用于消除跨来源重名，重命名和覆盖只能应用一次。

远程内容统一由设备更新，没有服务端模式。每份配置分别选择订阅及远程规则的更新出站，默认跟随设备规则；可显式选择直连、独立节点或组。显式出站的依赖图会检查自依赖和循环；跟随规则时的实际启动依赖由设备运行时决定。缓存路径按配置及定义摘要隔离；地理数据默认使用内核地址及更新设置，不提供无效的逐文件代理选项。

## 配置与规则

策略组可包含多个订阅、标签来源、手工节点和其他合法组。验证重名、保留名、循环、无效引用和空结果；发布前展示本地成员和远程来源摘要，远程实际成员待设备解析。空结果不自动改为直连，必须存在明确、有效的处理方式。

方案拥有一份明确有序的规则列表，混合单条规则、自建规则集、公共规则集、GEOIP及兜底规则。条件、参数和目标由类型化表单输入；支持批量、复制、启停、搜索及键盘可操作的排序。复杂条件采用条件组。兜底固定在末尾。

规则集维护内容，方案决定引用位置和目标。DNS、fake-ip及其他受支持客户端参数全部提供表单，高级字段按需展开。YAML可只读预览和导出，不作为缺失表单能力的编辑出口。

## 更新与发布

手工编辑可以保存草稿，也可直接点击“应用更改”完成保存与发布；发布执行结构、引用、来源、规则及固定内核校验，通过后原子切换。远程更新由设备完成，不自动改变发布版本。设备请求只消费已发布工件，不阻塞等待上游。

远程定义不依赖服务端缓存，首次发布也不访问上游。设备更新失败时的缓存状态在客户端查看，管理端不宣称知道远程健康。空组、非法引用或内核校验失败阻止本次发布，不破坏现行版本。

发布固定配置、远程定义和本地内容；回滚恢复这些内容，不回滚设备已经更新的远程缓存。下载配置和其资源通过版本关联，避免一次发布中混用资源。历史保留需要有界、可观测，当前有效版本和可回滚版本的必要资源不得被清理。

## 设备与身份

设备链接默认长期有效，可设置到期，支持暂停、恢复、吊销及轮换。普通发布或切换方案保持URL稳定；轮换创建新链接，默认立即废止旧链接。Token及资源下载权限贯穿主配置、provider和规则资源。

管理员可再次复制已建链接，因此敏感值采用可恢复加密而非只存不可逆摘要。界面默认遮蔽。加密密钥在SQLite外保存，恢复必须同时具备数据库、必要工件和密钥。

OIDC以issuer和稳定sub识别用户。管理员维护业务，使用者只访问被授权方案和自己的设备，不能通过管理接口枚举上游凭据；授权设备配置会包含必要的上游地址及请求头。首次登录不自动获得管理员。管理写请求执行授权、CSRF防护和并发版本检查。

IdP故障不影响有效设备下载现有发布；新管理登录可能不可用。应急处理归受限运维路径，不新增公网密码恢复平台。设备吊销不收回已下载的上游地址、请求头、节点凭据或缓存，最近下载不代表客户端已应用或节点连通。

## 界面

桌面优先，首版中英文、默认中文；浅色、深色、跟随系统。主导航为订阅、节点、配置、设备、设置。规则集、地理数据、使用者和运行状态放入设置。配置内提供策略组、分流规则、DNS、连接设置；规则集也可从规则编辑器直接管理。组成员以多选、搜索和预览维护，关系图只作辅助。

常用字段直接展示，高级字段渐进展开，所有输入有标签和具体错误。失败保留输入；多错误提供可定位的摘要。可拖动操作提供按钮和键盘替代。区分草稿、已发布、最近下载、设备远程更新与真实连接状态。

## 通用导入与完成条件

只导入用户主动提供的标准完整配置；保持显式组成员、规则顺序和 DNS 设置，不推断模板、目录或部署方习惯。未知字段、失效引用必须明确拒绝。导入预览确认后创建独立草稿，不自动发布。部署方负责其私有数据整理与迁移核对，产品不包含专属适配或私人预设。

新建配置必须明确选择订阅、节点或直连，生成一个默认组和兜底规则。不隐式选择以后新增订阅，不默认加入第三方规则或启用 DNS。设备按最近取得的已发布定义更新远程内容。

发布、部署和客户端验收分别报告。真实 OIDC 登录、客户端导入、刷新、链接替换和实际连接均须独立验收。

统一更新语义与迁移约束见 [ADR-0007](adr/0007-device-managed-updates.md)。
