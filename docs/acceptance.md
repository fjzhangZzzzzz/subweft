# 验收标准

本文定义可重复的完成条件，逐次运行结果和敏感证据保存在仓库外的受限工件中。当前所有应用验收均未执行。范围见[支持矩阵](support-matrix.md)。

## 核心业务

| ID | 必须验证的行为 |
|---|---|
| AC-01 | 全部日常增删改查、批量、启停及支持的高级字段由表单完成，无YAML编辑兜底 |
| AC-02 | 订阅导入各种约定格式；非法、超限和未知字段可定位，不能静默丢弃 |
| AC-03 | 上游刷新保留本地显示/排除设置；不确定匹配被提示；复制为手工节点后独立维护 |
| AC-04 | 多订阅、标签、手工节点和组自由组合；循环、重名、空组及失效引用按规则拒绝 |
| AC-05 | 规则顺序、规则集、DNS及全局参数渲染正确，所有实际迁移字段都有覆盖证据 |
| AC-06 | 方案复制后编辑相互独立；一个设备改绑不改变其他设备方案或凭据 |
| AC-07 | 发布及回滚使用一致来源/规则快照；运行中重启或中断不暴露半成品 |
| AC-08 | 新来源首次失败、上游超时、格式错误、空结果及非法配置均保留当前有效发布 |
| AC-09 | 有旧缓存时允许明确提示后发布其他修改；自动更新通过相同校验流程 |

## 授权与秘密

| ID | 必须验证的行为 |
|---|---|
| AC-10 | Pocket ID真实登录、退出、issuer/sub绑定及角色隔离；同邮箱或首次登录不提权 |
| AC-11 | 管理API逐资源授权、CSRF和并发修改保护；普通使用者看不到上游凭据 |
| AC-12 | 两设备独立下载；暂停、到期、吊销及轮换使目标失效，不影响其他设备 |
| AC-13 | Token授权覆盖配置、provider及规则资源；无效请求不返回伪装成功的占位配置 |
| AC-14 | 已授权设备在IdP不可用时仍能下载有效发布；不能由此绕过管理端认证 |
| AC-15 | 密钥缺失/错误时安全失败，不重建覆盖；数据库、磁盘快照和错误输出无意外明文副本 |
| AC-16 | 日志、浏览器错误、下载路径日志及校验输出不泄漏秘密；上游凭据不进入客户端配置 |
| AC-17 | 抓取拒绝未授权内网目标、重定向和DNS重绑定绕过，并执行体积、时间及并发限制 |

## 恢复、平台和客户端

- 从同一备份实际恢复数据库、密钥及必要工件；不借现场数据库证明恢复成功。
- 升级、重启后业务状态和设备凭据保留；数据库迁移失败不能留下伪健康实例。
- Linux amd64与arm64分别构建、运行、恢复及业务验证；模拟或构建成功的证据独立标注。
- 本机Clash Verge逐项验证首次导入、同URL更新、方案切换、轮换后的重新导入，以及是否产生重复配置。
- 比较迁移前后真实有效配置的组成员、规则顺序、DNS、启停与高级参数；结构变化不要求字节相同，但业务差异必须解释。
- 旧服务保留作回退，新子域名和设备链接验证通过后再评审切换。旧链接不兼容，不将旧入口改造为新服务授权层。

## 性能场景与目标

固定基准：10个订阅、共2,000个节点、5份方案、20台设备、较大公共规则集、10个并发配置下载。该规模不是产品数量限制。

| 指标 | 目标和测量边界 |
|---|---|
| 应用空闲RSS | ≤64 MiB；记录稳定时间、平台和构建 |
| 缓存配置下载P95 | 本机10并发≤300 ms；明确响应体大小和请求数，不含外网传输 |
| 请求路径 | 不同步等待上游抓取或校验 |
| 界面 | 大节点列表分页或虚拟化，表单输入和选择保持响应 |
| 资源峰值 | 应用、Mihomo子进程及容器总峰值分别记录，涵盖抓取、发布和规则处理 |

这些是尚待验证的目标。低空闲CPU、语法通过、容器健康和一次成功下载都不能替代吞吐、故障、恢复或客户端验收。

公开源码可以早于功能完成，README必须准确标明状态。实际替代须完成相关AC、平台与客户端、恢复、性能和迁移对照，保留可复查的脱敏索引。源码提交、推送、构建、发布、部署和验收分别报告。
