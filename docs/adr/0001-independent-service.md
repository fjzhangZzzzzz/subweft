# ADR-0001：采用边界明确的独立服务

状态：已接受。

## 背景

需求同时包括全部日常操作使用表单、保留现有有效Mihomo配置行为、自由组合来源和策略组、原生OIDC及独立设备下载授权。候选成熟产品能够提供部分能力，但不能直接满足这一组合。长期深度fork同样需要维护模型、表单、授权和上游冲突。

## 决策

以专用产品实现需求，复用适当的成熟库和固定Mihomo原生校验程序。产品源码与基础设施运维分开；本项目拥有业务模型及状态，部署方拥有主机、证书、安装、备份和监控。

采用Go、SQLite及内嵌React UI的单实例架构，不增加Redis、外部数据库或额外认证平台。详细行为和模块边界分别由[设计](../design.md)与[架构](../architecture.md)维护。

## 后果

维护责任包括安全更新、字段适配、数据库迁移、失败恢复、表单与真实客户端验收。自研的价值是减少日常配置、分发和排错成本，不以节省几十MiB内存作为主要理由。

Mihomo及依赖许可单独审查，独立校验不等于无再分发义务。所有能力以真实覆盖证据标注，首版边界由[支持矩阵](../support-matrix.md)限制。
