# ADR-0003：首个闭环采用SQLite内的自包含发布

状态：已接受的总体架构下的首个实现边界。

## 决策与原因

先以SS子集实现从表单到设备下载的完整流程。来源有效快照、配置正文、发布元数据和活动指针同存SQLite；业务对象和正文均加密。发布在同一事务内写入不可变正文与指针，减少早期数据库/文件双写的恢复状态。

初始渲染将来源节点展开为自包含 `proxies`，不生成额外provider或规则资源URL，因此设备凭据只需保护唯一配置下载。不会把原始上游地址或凭据带给设备。

定时来源更新只刷新快照；发布必须显式执行，避免将未确认的方案草稿自动激活。每方案保留最新20份发布，回滚切换正文，不覆盖当前草稿。来源缓存刷新改变编译代数，但不改变用户定义修订号，防止后台更新干扰表单编辑。

## 后果

这不是完整Mihomo能力声明。原provider客户端参数、规则集资源、自动发布和完整协议仍需按[支持矩阵](../support-matrix.md)扩展。在出现多资源发布需求时，仍需保证版本关联、一致提交、授权贯穿和恢复可用，不能退化为数据库与静态目录两套编辑权威。
