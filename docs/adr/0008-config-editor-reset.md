# ADR-0008：回到单配置生成器，先评审交互原型

状态：已接受。2026-10-30 用户确认交互原型评审通过；正式服务重写尚未开始。

日期：2026-10-30

## 背景

用户否决了此前用途工作区的实现，要求以 clash-config 的 `docs/web-ui-design.md` 为新起点。经过设计访谈确认以下收敛。本文取代 ADR-0006、ADR-0007 中与这些决定冲突的产品方向；旧代码和旧文档不能据此被视为已符合新设计。

## 确认的模型

- 单管理员、单配置。部署配置 OIDC issuer 与 `sub`；不提供用户、角色或租户管理界面。
- 订阅只保存名称、HTTP(S) 地址、所属池、启用状态与支持的客户端参数。固定高质量池、高流量池；每个订阅属于一个池。
- 策略组独立管理，支持 `select`、`url-test`，选择一个或两个池，可加入 `DIRECT`、`REJECT`。两池全选即全部订阅。不支持手工代理节点和组嵌套。
- 规则集与策略组独立。自维护规则集按用途命名，可混合完整域名、域名及子域名、IPv4/IPv6 CIDR；选择类型后展示对应字段说明和校验。公共规则仅支持 HTTP 来源、YAML 格式、`domain` / `ipcidr`，客户端加载内容。
- 分流规则独立指定匹配、目标和全局顺序。支持引用规则集、独立域名、域名后缀、关键词、IP CIDR、GEOIP；`MATCH` 兜底固定最后、可修改目标。
- 自维护集合自动生成可读的 `用途-domain`、`用途-ipcidr` inline provider，只生成非空类型。引用集合的规则在该位置相邻展开为域名、IP；整个集合一起排序。特殊例外可放在集合前面。
- 基础 DNS、端口等保留首次导入配置，随快照保存，首版只读。配置不提供通用 YAML 编辑器。
- 设备由 Subweft 管理独立授权，支持创建、复制链接、暂停、恢复、撤销、更换链接和可选有效期。所有设备下载同一当前发布版本；授权操作立即生效，不进入配置草稿。Nginx 不管理业务 token。

## 状态与边界

1. 日常配置编辑保存到唯一持久草稿，不自动发布。格式错误阻止保存；空组、引用等跨对象问题允许保留草稿，但阻止发布。
2. 发布前审阅业务变更和配置差异，检查当前草稿修订。修改使检查失效；只发布检查通过的同一修订。失败保留草稿和当前发布。
3. 发布历史为不可变快照。恢复只替换草稿，必须再次检查并发布新版本。
4. 新建分流规则时可就地创建策略组，两者一次保存；取消父表单不残留策略组。
5. 服务不拉取、解析、转换、缓存或代理订阅及公共规则，不提供节点健康和流量监控。客户端直接获取 HTTP provider。
6. 正式版本仍必须执行受约束、固定版本的 Mihomo 原生校验；所需 GeoDB 由部署预备，缺失阻止检查。原生解析成功不等于远端内容或连接可用。
7. 设备下载只读取已发布快照，不同步抓取上游。最近下载不代表设备在线或配置已应用。撤销不能收回已经下载的上游凭据。
8. 首次迁移从旧项目导入；之后数据库是唯一业务权威，不做 Git/CLI 双向同步。混合类型集合展开可能改变旧规则顺序，迁移必须展示差异，不承诺自动保持任意交错顺序的语义。

## 本轮交付与后续

先交付独立、可丢弃的单文件原型 [`web/prototype.html`](../../web/prototype.html)。七个导航页采用侧栏、列表、右侧表单；窄屏为折叠导航和全屏表单。原型仅有合成数据和内存状态，原生校验、发布及设备下载均明确标示模拟。

原型人工评审通过后，才基于此决策重写正式设计、架构、支持矩阵与实现计划，再实施正式产品。现有后端、运行数据和生产服务不属于本次变更。生产切换仍需单独迁移计划和真实客户端验收。

### 人工评审补充

用户认可原型主体，确认规则集导航位于分流规则之前；配置审阅采用逐行差异（左右对照 / 行内对比、行号、增删与文字高亮、上下文折叠），敏感地址脱敏且修改仍需可见。界面统一用「目标策略」「远程规则集」「自维护规则集」和「新增」「恢复到草稿」等动词。此次仅调整原型，未启动正式服务重写。

调整完成后，用户明确确认「评审通过」。此决策及本地 `prototype/accepted-ui-20261030` 分支中的原型作为正式实现基准；详细通过范围见[原型评审记录](../prototype-review.md#评审结论与实现基准)。
