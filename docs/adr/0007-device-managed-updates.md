# ADR-0007：统一由设备更新远程内容

状态：已接受。用户确认方向，需求及工程规范两项独立评审通过，无阻断项。

## 决策

Subweft 统一生成由设备更新远程订阅、远程规则集及地理数据的配置。服务维护表单、配置定义、手工节点和本地规则，负责不可变发布、设备授权及原生结构校验；设备内核负责远程内容下载、缓存、节点解析和健康检查。不提供服务端更新与设备更新的模式开关，不新增常驻代理内核或转换服务。

此决策替代 ADR-0005 中“远程内容全部缓存且上游地址只保存在服务端”的范围，以及既有设计、验收中依赖服务端远程快照的要求。历史发布、备份与密钥继续保留。授权设备会取得其配置引用的上游地址与必要请求头；普通管理接口仍不能枚举这些凭据。吊销只阻止后续 Subweft 下载，不能收回既有上游地址、节点或缓存。

## 模型及配置契约

1. 订阅仍是共享对象：名称、远程地址或本地节点内容、标签、启停、设备更新周期、请求标识及结构化请求头。远程来源只校验定义，不在保存、预览、应用或设备下载时访问上游。默认请求标识使用固定内核的 Mihomo 标识；可显式覆盖。远程内容的有效性留给设备，不能静默删节点。
2. 每份配置拥有“订阅更新”行列表，显示其已选择的订阅及更新出站；默认直连，允许选择本配置内的节点或策略组。出站属于配置中的引用，不能把一个配置的组名泄漏到另一配置。多个组引用同一订阅只生成一个远程定义，以原生 use 引用；各组独立的筛选、排除由内核执行。
3. 保留本地订阅、手工节点及表单导入；本地内容作为版本化鉴权资源或内联节点下发。远程订阅不显示虚构节点数量、刷新时间或节点列表；其名称变换和排除通过结构化的原生过滤/覆盖设置表达。已有按节点身份保存的远程覆盖不能静默丢弃：迁移保留并阻止受影响配置应用，明确提示转为可表达的匹配规则或本地节点集合。
4. 远程规则集有地址、行为、格式、更新周期及请求头，在配置引用处选择更新出站；本地规则仍是可编辑规则列表，发布冻结其内容。远程规则是否有缓存不再作为发布前提。
5. 地理数据保留远程地址及本地上传，渲染原生 geox-url、geo-auto-update、geo-update-interval。固定内核没有与规则集相同的逐项 proxy 字段，因此不提供无效的出站下拉。界面说明其首次下载依赖客户端可达性，后续更新遵循内核行为；不宣称可以使用尚未初始化的策略组启动。默认不擅自添加地理数据或第三方规则。
6. 发布固定配置定义、本地内容以及所引用远程定义，不固定远程节点或远程规则内容。回滚恢复上述定义；界面明确不回滚设备已经更新的远程缓存。设备主链接稳定，改绑、轮换、暂停、到期和吊销仍贯穿 Subweft 主配置及本地资源下载。

## 启动依赖和验证

- 静态依赖图覆盖组包含关系、节点 dialer-proxy、订阅更新出站和远程规则更新出站；拒绝缺失引用及自依赖/跨订阅循环。不把循环自动改为 DIRECT。通过独立手工节点或可直连订阅建立启动路径；图检查不等于网络可达性保证。
- 组含远程订阅时，其成员是动态的，不要求服务端持有节点缓存；仅在没有任何有效来源、手工节点、子组或显式内置出口时拒绝空组。不能为发布注入 DIRECT 或伪造节点。
- 原生校验运行在既有隔离环境，不能为验证访问真实上游。对远程内容使用仅在校验工作目录内存在的验证投影：远程订阅/规则引用转换为受控本地校验内容，依赖远程地理分类的部分标记为设备待验证，不把它们伪装成已通过内容校验。真实发布工件保留完整原生定义，验证投影绝不进入发布、预览或下载。投影差异采用白名单，只替换外部获取机制；原始出站、请求头、过滤表达式必须先独立验证，反例不能被投影掩盖。
- 验证结果和 UI 区分“配置结构检查通过”“远程内容由设备验证”“设备最近下载”；后台不提供缺乏反馈通道的远程健康/连接成功状态。自定义本地规则、手工节点、已上传地理数据继续执行完整相关校验。
- 配置预览、API 元数据、导入预览、审计、错误和版本比较中的远程 URL、请求头、节点凭据都脱敏。只有获授权配置下载及管理员显式编辑接口可取得必要原文；验证失败不输出内核原始日志。

设备订阅及规则缓存路径包含配置、来源和远程定义摘要，本地资源包含内容摘要；不同配置、地址变更、改绑和版本切换不得误用其他定义的缓存。回滚可能重新使用对应旧定义的已有缓存，不承诺回滚远程内容。

## 表单与使用用例

主导航保持订阅、节点、配置、设备、设置，不增加更新模式或新建模页面。

| 用例 | 表单和反馈 |
|---|---|
| 添加订阅 | 名称、地址、标签；高级区为更新周期、请求标识、请求头和健康检查。保存后显示“由设备更新”，没有服务端刷新按钮 |
| 组合订阅 | 配置策略组多选任意个订阅，保留手工节点、其他组及筛选条件；远程成员展示来源摘要而非零节点 |
| 选择更新路径 | 配置的订阅更新列表每行一个“直连／本配置节点或组”下拉；规则集引用也提供同义控件；依赖错误就地定位 |
| 编辑规则 | 规则列表按顺序增删改查；新增远程规则集与维护本地规则分开表单，远程条目不显示服务器缓存错误 |
| 应用配置 | 检查定义和引用，明确远程内容待设备验证；原子发布，不等待上游，不将失败伪装成成功 |
| 查看设备 | 复制、导入、改绑、轮换、暂停和吊销；显示最近下载，说明既有上游凭据不会被追回 |

交互验收必须覆盖桌面与窄屏、浅/深色、长表单滚动、粘性操作区、遮罩点击和 Escape 关闭、未保存确认、键盘焦点、失败保留输入、字段级错误与安全预览。完整日常操作由表单完成，无 YAML 编辑兜底。

## 升级和回退

迁移在独立备份恢复副本上验证，然后随产品版本执行一次幂等、事务化升级；失败不部分覆盖数据。保留对象 ID、启停、标签、显式组成员、规则顺序、DNS、设备及身份。原有客户端更新周期、请求头和出站迁入对应定义/配置引用；仅有服务端代理 URL 的设置不能自动变成设备组名，必须提示待处理，不能静默遗漏。未指定出站明确默认直连。跨配置缺失出站、既有远程按节点覆盖等冲突保留原输入并阻止相关应用，不阻止无关配置。

服务端调度与刷新入口退役，旧接口明确拒绝而非执行外发；移除界面中的自动发布、抓取代理、缓存确认等旧操作。旧数据库中的缓存和历史发布在迁移中保留用于准确恢复；新配置不再依赖或刷新它们。回退使用升级前数据库和匹配旧程序、镜像及密钥，不能仅切换旧二进制读取已迁移数据。

## 交付与验收门槛

1. 方案：独立需求与规范评审通过，无未解决阻断项，才允许修改运行代码。
2. 实现：多配置不同出站、多订阅复用、标签、显式启停、过滤、手工节点和 dialer-proxy、规则顺序、DNS、地理数据、秘密脱敏、旧版恢复、迁移失败原子性与幂等必须有行为测试。用“上游不可达或主动 panic 的抓取器”证明保存/预览/发布/下载不访问上游。
3. 内核：固定 Mihomo 在隔离冷目录下对合成 HTTP 上游实际验证订阅及规则的直连和代理更新、空缓存首次启动、循环拒绝、上游失败后的设备缓存行为。同时验证按实际 User-Agent 返回完整配置 YAML 的订阅提取、沿用设备工作目录时变更地址与回滚。不得借用户现有客户端缓存冒充冷启动通过。真实凭据只在部署方受限环境验证。
4. UI：真实浏览器逐页完成表单流程、导航和交互，并检查截图与响应式布局；修复后回归。必须走通旧覆盖冲突定位、表单转换为匹配设置或本地节点、解除阻断并发布的全过程。没有用户登录会话时使用隔离测试 OIDC 和脱敏数据，不绕过生产认证。
5. 发布：公开仓库只能包含通用代码/示例/长期文档，三个平台免费 CI、原生校验、恢复与适当性能测试通过。同步设计、架构、支持矩阵、文档导航及 AC-03/07/08/09/11/16/17，清除旧服务端缓存与凭据边界的矛盾承诺。产品拟升 0.2.0-rc.1；运维包独立递增并锁定准确镜像与摘要，不覆盖旧工件，不启用付费 CI。
6. 部署：使用已发布正式 Ansible 包，升级前一致性备份、版本与主机核对、prepare_only、最小切换、就绪/公网/认证/授权验证、升级后备份与同快照恢复。保留旧服务及既有有效设备入口。上线后明确列出仍待用户在 Clash Verge 完成的首次导入、更新、替换和实际代理验收，不将服务器 UI 检查等同用户客户端验收。
