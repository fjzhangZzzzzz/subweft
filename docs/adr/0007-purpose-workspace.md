# ADR-0007：以配置和用途组织试用工作区

状态：已接受，首版实现；真实客户端及生产验收尚未完成。

## 决定

配置内提供「订阅与节点」「分流」「DNS 与连接」三个入口，默认进入分流；无来源时进入订阅页。空状态可直接开始一份尚不可应用的配置，不隐式加入直连、第三方规则或未来来源。

用途只是策略组及指向它的规则的联合编辑视图，不存储另一份用途实体。编辑在本地草稿中完成，一次「应用更改」保存、校验并原子发布。已有规则顺序不因用途聚合而改变；新增规则位于 MATCH 之前。全部规则入口保留精确排序、公共规则、直连、复杂条件与启停。不能删除仍被引用的用途。

订阅池属于配置，只包含名称和明确的订阅 ID 列表。组可以同时选订阅和池，编译时展开并去重，不修改存储定义。池不支持嵌套、继承或标签表达式；引用中的池不能删除，改名同步本配置的组引用。已存在的 allSources/tags 保留行为并明确提示，可由用户转换为当前明确选择；新编辑不再提供动态选源开关。

proxy provider key 使用订阅名称，rule provider key 使用规则集名称；use/RULE-SET 引用同步生成。资源 URL、缓存路径、版本权限仍使用内部稳定标识。同一来源在一份配置内只产生一个 provider。对已有筛选语义，按有效快照生成组级精确成员 filter，保留名称正则和类型排除的结果，不再按组复制 provider；组排序不改变 provider 名称或资源 ID。输出作用域中的 provider 重名明确拒绝。

「获取订阅链接」在配置内创建具名、可独立撤销的凭据。在同一列表维护名称、期限、暂停/恢复、更换链接及撤销，到期状态优先于有效状态显示；底层设备授权与版本绑定不变。保存草稿、预览、历史恢复、复制配置为次要操作。

## 边界与取舍

本版订阅、手工节点与规则资源仍沿用共享存储；订阅池、组、规则和客户端设置属于配置。未把共享来源改成配置私有，避免在交互试用时复制上游凭据。来源表单保存共享库定义，当前配置的设备版本仍须显式应用；每个引用配置分别确认。界面区分未保存、待应用和可供客户端刷新的状态。规则集仍使用受管理的版本化资源，本版不改为 inline。

来源抓取、原生校验、不可变发布、设备授权的技术边界不变；下载不抓取上游，失败保留现行配置。系统部署、密钥和备份仍属于部署方。本版不修改生产或引入旧入口兼容。

## 自动更新与应用边界

发布记录被使用来源、手工节点、资源的定义摘要（不对管理 API 暴露）。自动更新使用活动版本的配置及自动更新开关，仅当来源定义未变化时接受新的远程缓存。手动改名、修改抓取参数、节点覆盖、手工节点或本地规则内容，均要求显式应用；无关来源编辑不阻塞当前配置。源缓存时间、错误、节点快照和远程资源内容不属于定义摘要。摘要不是新业务对象，也不是一套来源草稿/版本 UI。

旧发布缺少摘要时继续提供原工件，须先显式应用一次，才恢复自动内容更新。回滚到这样的旧版也遵循此规则。管理状态根据缓存编译结果和活动版本比较待应用状态，不抓取上游、不启动校验子进程。

## 交互收敛

用途内常见域名、IP、规则集直接添加；复杂匹配保留结构化表单。新增和改名使用稳定内部目标，在完成编辑时统一替换为名称，不向用户显示占位标识。用途内不提供跨用途排序；全局规则视图显示真正的优先级，直连/拒绝计数常驻，兜底入口只出现一次。

节点来源显示已选名称，已有选择默认折叠；常用 DNS 与连接参数优先，高级全局字段和自动更新/地理资源按需展开。手机改为顶部导航，按钮至少 44px，避免侧栏持续占用横向空间。

参考 [Clash Verge Rev 的配置操作菜单](https://github.com/clash-verge-rev/clash-verge-rev/blob/dev/src/components/profile/profile-item.tsx) 将对象操作放在对象附近，参考 [MetaCubeXD](https://github.com/MetaCubeX/metacubexd) 的策略/规则分区与响应式体验。仅借鉴交互原则，未复制代码或引入依赖；Subweft 的应用与设备下载边界不变。

## 验证

编译测试覆盖可读名称、共享 provider 的成员筛选、排序稳定性、重名拒绝、订阅池错误引用，以及锁定 Mihomo 的原生 bundle 校验。人工检查来源、池、用途、规则、应用和链接流程；不能由此推断真实节点连通或生产替代完成。
