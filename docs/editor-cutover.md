# 新编辑器迁移与切换

开发阶段不改生产、不复用旧数据库；旧服务持续可用。

1. 在独立目录部署新程序、SQLite、独立密钥、固定 Mihomo 与 GeoDB；Nginx 只负责 TLS 和反代，配置唯一 OIDC issuer + sub。
2. 从旧项目整理支持子集的配置副本。显式处理手工节点、file/classical 规则和超过两个池的引用关系；不自动删弃字段。原 file 规则内容需整理为支持的 inline 或远程 YAML。
3. 初次导入后审阅订阅池、策略组成员、规则顺序、MATCH、基础 DNS/端口、自动生成的 provider 名称及 path。用途集合合并须逐项核对交错顺序，不宣称语义自动等价。
4. 通过原生检查并发布，创建单个试验设备。用真实客户端更新，确认真实上游订阅、远程规则、GeoDB、DNS 和目标连接行为。
5. 人工签收后逐个设备换用新授权 URL；旧 URL 和旧服务保留在约定回退期。不得让 Nginx 继续承担设备 token 逻辑。
6. 故障时将客户端恢复为旧 URL，旧服务继续服务；不要用旧程序打开新数据库。新数据库与其独立密钥必须配对备份和恢复。

本阶段仅准备此方案，未执行生产部署或切换。容器验收工具中旧业务 API 场景需要按新接口另行更新验证，不能沿用旧通过结论。
