# 人工验收入口

本候选用于验收完整首版。源代码、候选工件和测试通过不代表已经替代生产。当前证据和限制集中在[能力状态](status.md)；逐项门槛见[验收标准](acceptance.md)。

## 先体验完整业务

在源码目录运行 `python tools/dev.py`，打开 `http://127.0.0.1:18880`，选择统一身份登录，再以测试管理员继续。再次启动保留独立开发状态；Ctrl+C 停止服务。开发状态和密钥位于 `output/dev`，不要上传到 Git。

首次准备可全部通过界面完成：

1. 在“系统 → 导入现有配置”上传或粘贴 `http://127.0.0.1:18881/migration.yaml` 返回的合成配置。预览确认后创建草稿并刷新来源；导入不发布、不覆盖已有方案。
2. 在“来源”查看 primary/quota，编辑抓取设置和客户端 provider，查看节点并设置本地名称、排除及备注。另添加手工节点；协议列表有 13 项，高级参数为可增删的结构化字段，敏感值默认隐藏。
3. 在配置中检查显式组成员，组合多个订阅、手工节点及其他组。
4. 在规则页新增、编辑、复制、排序、批量启停或删除；在规则资源页维护自建规则集或 HTTP 规则集。DNS、policy 顺序、fallback 和客户端参数均使用表单。
5. 保存草稿，查看脱敏配置，校验并发布。再修改一次并发布，在历史中回滚；未发布草稿不应影响现有设备下载。
6. 新增两台设备；分别复制链接。测试暂停/恢复、到期、改绑、轮换、吊销。改绑保持地址，轮换更换地址；只应影响目标设备。
7. 在“使用者”添加 `fixture-member`，仅授权一个方案。退出后在测试身份页选择 test member：只能维护自己的获授权设备。重新以管理员登录，停用账号或移除方案授权，后续下载应失效。
8. 在“系统”下载加密备份。备份不包含独立主密钥；按[恢复](container.md#备份恢复与升级)在新目录恢复，不能覆盖现行数据库来试验。

上述地址仅是合成测试源，没有可用代理。也可以添加 `http://127.0.0.1:18881/all.yaml`，获得 13 协议代表节点。看到节点、通过配置校验、下载成功分别只证明对应环节。

## 迁移自己的旧配置

标准完整配置经预览确认后创建独立草稿；未包含的内容可通过表单补充。


逐项对照旧配置的实际成员集合、规则顺序、DNS/policy/fallback、全局参数和禁用输入。文件结构和资源路径允许变化，业务语义差异必须解释。导入出错时只保存限时加密预览，不能生成半份业务数据；确认仅创建草稿，发布仍需原生校验。

## 真实 Pocket ID / Passkey

按[容器安装](container.md)准备新子域名的 HTTPS 验收实例。也可在 Windows 单独使用环回 HTTP 应用回调加真实 HTTPS issuer；`SUBWEFT_LOCAL_HTTP=true` 仅放开明确的环回 IP 监听及应用地址，不允许远程 HTTP 身份服务。

在 Pocket ID Administration → OIDC Clients 创建 confidential client，准确登记 `<应用基址>/auth/callback`，保存 client ID 和 secret。通过 OIDC Data Preview 核对管理员实际 `sub`；部署的 `SUBWEFT_ADMIN_SUBJECTS` 使用该值，不能填写邮箱或显示名称。issuer 采用发现文档中的精确 `issuer`，不是把整个 discovery URL 填进去。参考 [Pocket ID 接入说明](https://pocket-id.org/docs/setup/connect-an-app)和[claims/预览说明](https://pocket-id.org/docs/guides/scopes-and-claims)。

亲自完成 Passkey 登录、退出、本地角色隔离和第二个使用者授权。Subweft 退出撤销本应用会话，不代替 Pocket ID 全局退出；Pocket ID 停用本身不推导 Subweft 现有 8 小时会话或设备立即失效，立即撤权使用本应用“停用使用者/移除方案授权”。现有设备下载不依赖 IdP 实时在线。

## 本机 Clash Verge

先保留原配置和原服务。为本机生成专属设备，再按顺序操作：

1. 使用“导入 Clash Verge”或复制链接粘贴到客户端远程订阅中，确认产生的配置名称、节点、provider、规则集与 DNS。记录客户端实际版本与其 Mihomo 版本；本服务固定校验 v1.19.33，客户端内核差异需单独检查。
2. 明确选择测试配置并检查实际连接；合成节点只用于导入检查，真实连接必须使用自己的有效来源。
3. 修改并发布方案，在客户端刷新同一订阅，确认取得新配置，且没有因为普通刷新新增重复项。
4. 只改绑这台设备，在客户端刷新，确认订阅 URL 保持不变，方案变化生效，另一台设备不变。
5. 轮换链接，确认旧链接不能下载。使用新链接重新导入或编辑现有远程订阅地址，明确处理客户端可能新增的重复配置。
6. 暂停或吊销后刷新应失败；客户端可能继续使用先前下载的代理，这是预期边界。恢复暂停后再刷新应成功。

一键导入会交给客户端处理，不能保证覆盖既有配置，也不会远程控制客户端。首次导入、同 URL 刷新和新 URL 替换须分别验收。只有上述真实登录、迁移对照及客户端流程通过后，才评审生产切换和部署方原服务退役。
